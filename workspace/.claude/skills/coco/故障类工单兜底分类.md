# 故障类工单兜底分类

本文档用于当精确规则无法唯一命中时的兜底场景。兜底规则仅在以下条件下触发：

1. 工单类型明确为故障类（FW038）；
2. 工单对象已明确或高度倾向某一标准对象；
3. 无法命中精确分类规则中的任何一条；
4. 不存在冲突对象或排除信息。

**兜底使用顺序**：
1. 优先匹配精确分类规则；
2. 无法唯一命中精确规则，但对象明确时，读取本文档中该对象的兜底规则；
3. 只能选择该对象对应的兜底规则；
4. 根据选中规则的必填字段检查全部原始工单，字段完整则自动派单，字段缺失则自动退回申请人；
5. 对象不明确、候选操作方冲突或存在无法拆分的多操作方诉求时，才人工处理。

## 兜底规则列表

### FB-001 堡垒机登录失败待定位

| 项目 | 内容 |
|---|---|
| 规则ID | FB-001 |
| 标准对象 | 堡垒机 |
| 已确认对象别名 | 堡垒机、4A、运维审计平台、跳板机 |
| 一级分类 | 堡垒机 |
| 二级分类/兜底场景 | 登录失败待定位 |
| 适用条件 | 工单明确涉及堡垒机对象（标题/content/malfunction_appearance中出现"堡垒机""4A""跳板机"等），且描述服务器/机器登录失败、无法登录、连接问题，但**无法明确区分**是密码过期、密码不正确、机器锁定还是宕机。仅出现"无法登录""连不上""连接失败"等通用描述，未伴随"密码错误""口令错误""认证失败""账户锁定""用户被锁""被禁用""宕机""连接超时""无法ssh""闪退"等明确特征。 |
| 排除条件 | 若同时出现密码相关明确描述（密码错误/口令错误/认证失败），应走精确规则"密码不正确"；若出现账户锁定描述，走"机器锁定"；若出现宕机/连接超时/无法ssh/闪退，走"宕机"；若涉及root权限问题，走"无权限"。 |
| 涉及字段信息（必填） | ip、用户（都要满足其） |
| 操作方 | 对应中心环境组（上海-张嘉瑾，苏州-孙坤铭），根据实际情况再转派 |
| 判断逻辑 | 1. 判断工单对象明确为堡垒机；2. 识别为登录/连接类问题但无法定位具体原因；3. 检查必填字段：包含IP或用户信息；4. 字段完整并且ip正常则自动派单；5. 字段缺失则退回申请人。 |
| 规则依据 | 历史工单中多条堡垒机故障仅在初期描述为"无法登录""连不上"，需经排查后才能确定具体原因。精确规则要求明确细分，对于无法细分的场景，采用兜底处理。 |
| 待业务确认事项 | 暂无。 |

## 兜底规则优先级速查

当对象明确时，按以下优先级选择兜底规则：

1. 堡垒机登录/连接问题无法细分 → **FB-001**
2. 数据库连接异常无法细分 → **FB-002**
3. Redis故障无法细分 → **FB-003**
4. NAS访问异常无法细分 → **FB-004**
5. 物理机/虚拟机故障无法细分 → **FB-005**
6. 对象完全不明确 → **FB-006**

**禁止行为**：
- 禁止为降低人工处理率而猜测对象；
- 禁止在对象不明确时选择兜底规则；
- 禁止在能唯一命中精确规则时使用兜底规则；
- 禁止用端口反推对象（如3306不能单独确定数据库）；
- 禁止仅凭操作方相同合并不同对象。
