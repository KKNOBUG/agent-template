# 服务请求类工单兜底分类

本文档用于当精确规则无法唯一命中时的兜底场景。兜底规则仅在以下条件下触发：

1. 工单类型明确为服务请求类（FW039）；
2. 工单对象已明确或高度倾向某一标准对象；
3. 无法命中精确分类规则中的任何一条；
4. 不存在冲突对象或排除信息。

**兜底使用顺序**：
1. 优先匹配精确分类规则；
2. 无法唯一命中精确规则，但对象明确时，读取本文档中该对象的兜底规则；
3. 只能选择该对象对应的兜底规则；
4. 根据选中规则的必填字段检查全部原始工单，字段完整则自动派单，字段缺失则自动退回申请人；
5. 对象不明确、候选操作方冲突或存在无法拆分的多操作方诉求时，才人工处理。

## 兜底规则优先级速查

当对象明确时，按以下优先级选择兜底规则：

1. 堡垒机服务请求无法细分 → **FS-001**
2. 数据库服务请求无法细分 → **FS-002**
3. DFTM服务请求无法细分 → **FS-003**
4. 软负载服务请求无法细分 → **FS-004**
5. 虚拟机/虚机相关服务请求无法细分 → **FS-005**
6. 工具安装服务请求无法细分 → **FS-006**
7. NAS服务请求无法细分 → **FS-007**
8. 对象完全不明确 → **FS-008**

**禁止行为**：
- 禁止为降低人工处理率而猜测对象；
- 禁止在对象不明确时选择兜底规则；
- 禁止在能唯一命中精确规则时使用兜底规则；
- 禁止用端口反推对象（如3306不能单独确定数据库）；
- 禁止仅凭操作方相同合并不同对象。
